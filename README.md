# Git Smart Commit ZQH

一个用于 Codex 的 Git 提交技能：先审查改动，再由你选择或编辑 commit 和分支名，最后确认是否创建本地提交。**新建分支禁止使用 `codex` 前缀。**

仓库名为 `Git.SKILL`，技能名为 `git-smart-commit-zqh`，调用时使用后者。

## 功能

- 先尝试启动一个独立审查代理，检查改动、风险、测试情况和合理的提交分组；无法使用代理时会说明并由主代理审查。
- 提供完整 commit 候选，也允许逐项编辑类型、模块、标题和正文。
- commit 确定后，再生成相关分支候选，支持自定义名称或保留当前分支。
- 在你明确确认前，不切换分支、不暂存、不提交；推送和创建 PR 需要另行授权。

## 安装

需要 Git，以及支持本地技能的 Codex 环境。独立审查代理和弹窗选择取决于当前宿主是否提供相应工具；缺少弹窗时会改用聊天中的编号选项。

新安装可以放在用户技能目录：

```bash
mkdir -p "$HOME/.agents/skills"
git clone https://github.com/zhang-qihao/Git.SKILL.git \
  "$HOME/.agents/skills/git-smart-commit-zqh"
```

也可以放在目标仓库的 `.agents/skills/git-smart-commit-zqh`，仅供该仓库使用。目录规则参见 [OpenAI 官方技能文档](https://learn.chatgpt.com/docs/build-skills#where-codex-loads-local-skills)。

如果已经安装在 `~/.codex/skills/git-smart-commit-zqh` 且能正常发现，更新现有副本即可；避免在多个目录重复安装同名技能。更新后如果仍显示旧内容，重新打开会话或重启 Codex。

## 使用

在需要提交的仓库聊天中明确调用：

```text
$git-smart-commit-zqh 帮我审查当前改动，并让我选择 commit 和分支。
```

也可以提前指定模板：

```text
$git-smart-commit-zqh 帮我准备提交。
commit 使用 feat(<模块名>): <改动信息>，正文使用中文列表。
新分支使用 feat/<模块名>-<英文简述>，禁止 codex 前缀。
```

技能也允许按提交意图自动匹配。安装了多个 Git 提交技能时，明确写出 `$git-smart-commit-zqh` 可以避免选错。

## 工作流程

1. 读取状态、diff、近期提交风格和项目说明，识别本次提交范围。
2. 尝试启动一个审查代理，并运行适用的检查。
3. 展示 2–3 个完整 commit 候选；你可以选择候选或逐项编辑。
4. commit 确定后，选择新分支名或保留当前分支。
5. 展示完整提交信息、文件范围、检查结果及将执行的本地操作，等待明确确认。
6. 确认后重新核对改动，按所选名称创建分支（如需要）、暂存选定内容并提交，报告 commit hash 和剩余改动。

选择分支本身不代表同意提交。多个独立改动会分别确认提交范围；没有可提交内容时会直接说明。

## 默认 commit 格式

未指定其他模板且仓库没有要求时，使用带模块的 Conventional Commits，正文默认中文：

```text
feat(auth): 增加登录状态校验

- 增加会话过期检查
- 补充未登录场景的处理
```

类型根据实际改动选择，如 `feat`、`fix`、`docs`、`refactor`、`test` 或 `chore`。你提供的提交模板优先于默认格式。

## 分支命名规则

**通过本技能新建的分支，名称不能以 `codex` 开头，不区分大小写。** 候选生成、自定义输入和实际创建前都会检查；创建后还会核对当前分支是否与确认的名称完全一致。

| 情况 | 示例 | 处理 |
| --- | --- | --- |
| 按改动类型命名 | `feat/auth-add-login` | 允许 |
| 修复分支 | `fix/api-handle-timeout` | 允许 |
| 文档分支 | `docs/readme-add-usage` | 允许 |
| 应用常见默认前缀 | `codex/add-login` | 拒绝 |
| 其他分隔符或大小写 | `codex-add-login`、`codex_add_login`、`Codex/add-login` | 拒绝 |
| 保留已经存在的当前分支 | 当前处于 `codex/old-work` | 仅在明确选择“保留当前分支”时保留 |

命名顺序为：符合规则的用户模板 → 符合规则的仓库惯例 → `<type>/<scope>-<slug>`。模板或自定义名称不符合规则时，会回到分支选择，不会偷偷替换成另一个名称。已有分支不会被自动重命名或删除。

### 为什么 Codex 默认前缀不能直接沿用？

本技能把“不要使用 `codex` 前缀”写成了明确的用户偏好，并在默认调用提示中重复说明。即使应用给出 `codex/` 默认建议，也应使用你确认的完整分支名，不再额外添加前缀。

如果某个创建工具会强制添加前缀，技能会在已授权范围内选择能够保留原名的路径；如果没有可用路径，或宿主的更高优先级指令强制要求该前缀，则在创建之前停止并说明原因。

这是一套技能工作流规则，不是 Git hook，也不修改应用的全局设置；未加载本技能的其他聊天不受它约束。希望其他聊天也遵守时，可将下面的偏好加入应用的个人指令：

```text
创建 Git 分支时，禁止使用任何以 codex 开头的分支名（不区分大小写）。
使用我确认的完整分支名，不要添加应用默认前缀；无法保留名称时先停止并说明原因。
```

## 操作边界

- 只暂存明确确认的文件或代码块，保留其他改动。
- 不自动混入已有暂存内容、敏感文件或本地环境文件。
- 不强制切换分支、不覆盖未提交改动、不改写历史。
- 必须完成的检查失败时，不会把提交方案标记为可执行。
- 本地提交、推送和创建 PR 分别取得授权。
